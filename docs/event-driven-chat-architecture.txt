Optional observability stack (Vector/ELK) can be attached to each container
to collect logs, metrics, traces; shared config via .env / secrets manager.

Communication paradigm (publish-subscribe):

- Clients send messages via WebSocket/HTTP to any gateway instance (publishers).
- Gateways publish standardized events (e.g., `chat.message.sent`) to MQTT topics
  that logically represent rooms/users; events are immutable and ordered per topic.
- Specialized workers subscribe to those topics; each worker category focuses on a
  concern (persist, notify, analytics) and can scale independently.
- Gateways also subscribe to delivery topics (e.g., `chat.message.delivered`) to
  push updates back to connected users in real time.
- Since producers and consumers decouple through the broker, components can join
  or leave without tight coupling—the broker buffers events and forwards them to
  every subscriber holding the relevant routing key.
